# 1. 🧱 DATABASE SCHEMA (lean but scalable)

Don’t over-normalize. Keep it flexible.

## Products table

```json
{
  "id": "prod_123",
  "name": "Kids Lion Name Towel",

  "age_group": ["kids"], 
  "gender": ["unisex"],

  "themes": ["animals"],
  "styles": ["initials"],

  "price": 499,
  "is_active": true
}
```

---

## Tags table (IMPORTANT)

```json
{
  "product_id": "prod_123",
  "tags": [
    "best_seller",
    "bundle_friendly",
    "safe_for_mixed_group",
    "good_for_return_gifts"
  ]
}
```

👉 Keep tags:

* flexible
* string-based
* easy to add/remove

Don’t over-structure this.

---

## Occasion config (THIS is your engine)

```json
{
  "occasion": "return_gifts",

  "boost_tags": {
    "bundle_friendly": 40,
    "safe_for_mixed_group": 30,
    "best_seller": 20
  },

  "penalty_tags": {
    "niche_design": -25
  },

  "preferred_styles": ["initials", "minimal"],
  "preferred_themes": ["animals", "florals"]
}
```

👉 This lets you:

* tweak business logic without touching products
* run experiments easily

---

# 2. ⚙️ FILTER API STRUCTURE

## Request

```json
{
  "occasion": "return_gifts",
  "filters": {
    "age_group": ["kids"],
    "gender": ["female"],
    "themes": ["animals"],
    "styles": ["initials"]
  },
  "sort": "recommended"
}
```

---

## Backend logic (simplified)

```pseudo
products = fetch all active products

if filters:
  apply filters (AND logic across groups, OR within group)

if occasion:
  score = 0

  for tag in product.tags:
    score += boost_tags[tag]
    score += penalty_tags[tag]

  if product.theme in preferred_themes:
    score += 10

  if product.style in preferred_styles:
    score += 10

sort by score DESC
```

---

## Response

```json
{
  "products": [...],
  "applied_context": "return_gifts"
}
```

# 4. 🔥 WHAT YOU SHOULD NOT DO

Let me be blunt here:

### ❌ Don’t:

* create 20 filters
* expose tags directly
* force a questionnaire
* hard-assign occasion to products

### ❌ Don’t:

* mix age + gender into one field
* create deep hierarchies
* overfit for edge cases

---

# 5. 🧠 THE REAL POWER MOVE (most people miss this)

Add **precomputed scores**

Instead of calculating every time:

```json
{
  "product_id": "prod_123",
  "scores": {
    "return_gifts": 87,
    "wedding": 62
  }
}
```

👉 This:

* speeds up listing
* stabilizes ranking
* lets you manually tweak top performers
